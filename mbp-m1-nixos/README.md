## Changelog

### Added nix-ld (Claude Code VS Code extension)
- `programs.nix-ld.enable = true;` provides a compatible dynamic linker so prebuilt Linux
  binaries can run on NixOS, needed for running e.g. Claude Code in VS Code.
- Fixes the Claude Code extension error "Could not start dynamically linked executable"
  (exit code 127, see https://nix.dev/permalink/stub-ld).
- After `nixos-rebuild switch`, fully restart VS Code (close all windows) and reload the
  extension. If a binary still complains about a missing `.so` file, add the library via
  `programs.nix-ld.libraries = with pkgs; [ ... ];`.

### Added Python
- **System packages:** `python3` (interpreter, includes `venv` and the standard library).
- On NixOS, avoid `pip install` into the system Python. Use a virtual environment per
  project instead:
  ```bash
  python3 -m venv .venv
  source .venv/bin/activate
  pip install <package>
  ```
  Or use `nix-shell -p python3Packages.<package>` for a temporary environment.

### Added fastfetch
- **System packages:** `fastfetch` (system information tool). `btop` was already installed
  (see "Added packages, Samba server"), so nothing changed for it.

### Added LibreOffice and VS Code
- **System packages:** `libreoffice-qt6-fresh` (office suite, Qt6 build that fits KDE Plasma)
  and `vscode` (Visual Studio Code).
- `vscode` is unfree software; this is already allowed by `nixpkgs.config.allowUnfree = true;`.
- Dutch spell checking / hyphenation for LibreOffice is not added yet; add
  `hunspellDicts.nl_nl` (and optionally `hyphenDicts.nl_NL`) to the package list if needed.

### Added packages, Samba server
- **System packages:** `git`, `openssh` (provides `ssh-keygen`), `btop`.
- **Samba server:** enabled via `services.samba` with a single share `shared`
  (`/home/rvdveldt/shared`, user `rvdveldt` only, no guest access).
  The firewall is opened automatically (`openFirewall = true`).
- **WS-Discovery:** `services.samba-wsdd` so the share shows up in Windows.
- **Directory:** `systemd.tmpfiles.rules` creates `~/shared` if it does not exist.

### Network discovery for Dolphin
- **Avahi (mDNS):** `services.avahi` with `nssmdns4` and `openFirewall`, so the
  Synology can be found by name and `*.local` hostnames resolve.
- **WS-Discovery:** UDP port 3702 opened in the firewall (`networking.firewall.allowedUDPPorts`).

### zsh as default shell
- `programs.zsh.enable = true;` enables zsh system-wide (adds it to `/etc/shells`).
- `users.users."rvdveldt".shell = pkgs.zsh;` makes it the login shell of the user.
- Log out and back in (or reboot) for the new shell to take effect in the desktop session.
- On the first zsh start the new-user setup wizard may appear; press `q` to skip it
  or `0` to create an empty `~/.zshrc`.

## Apply

```bash
sudo cp configuration.nix /etc/nixos/configuration.nix
sudo nixos-rebuild switch
```

Samba has its own password database, so set a password once after the first rebuild:

```bash
sudo smbpasswd -a rvdveldt
```

## Connect to the share

- macOS Finder: `Cmd+K`, then `smb://<vm-ip-or-hostname>/shared`
- Windows: `\\<vm-ip-or-hostname>\shared`
- Linux: `smbclient //<vm-ip>/shared -U rvdveldt`

Use the VM's IP (`ip a`) if the hostname does not resolve. In Parallels, the
network mode must be *Shared* or *Bridged* for the Mac to reach the VM.

## Troubleshooting

```bash
systemctl status samba-smbd
testparm            # validates the generated smb.conf
```

## Synology not visible in Dolphin (`smb://` / `network:/`)

Browsing the network relies on multicast/broadcast discovery, which is fragile.
Checklist:

1. **Parallels network mode:** *Shared* (NAT) does not forward multicast to the
   physical LAN, so discovery fails. Use *Bridged* (Default Adapter) for discovery.
2. **Synology:** Control Panel -> File Services -> SMB -> Advanced settings, and
   enable the Bonjour/WS-Discovery options (wording varies per DSM version).
3. **Bypass discovery:** type the address directly in Dolphin, e.g.
   `smb://<synology-ip>/` or `smb://<synology-name>.local/`. This also works in NAT mode.
4. **Test from a terminal:**
   ```bash
   smbclient -L //<synology-ip> -U <synology-user>
   avahi-browse -a -t   # lists mDNS services seen on the network
   ```
